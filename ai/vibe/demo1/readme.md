# 轻松上手Vibe Coding

想去用AI生成写代码，但AI生成的要不是“幻觉代码”，看起来像那么回事，一跑就出错。要么是屎山代码，能跑，但是乱的想改都不知道从哪下手

这个指南，不是怎么写代码

- 新手 自然语言编程
- 不要急于写代码，先思考，规划md文件
    每次prompt都会自动带上规划，保持一致性，有整体的约束

## 操作核心方法
- 第一步：规划就是一切。
不要上来就让AI去写代码，先强制它去读懂你的技术栈和项目规划（/init）
就好像你不会让新来的员工直接干活，去阿里入职 阿里Java 员工手册，等
得让他熟悉公司业务流程一样，AI生成的代码逻辑清晰多了。
新手把codex，cc 作为工具，把他们当伙伴，同事，助手。 

## demo
场景 用React + Tailwindcss 实现一个任务清单（代办）页面

Vibe 新兵:直接上手写代码 容易幻觉，屎山
    -要不要本地存储，
    -要不要API远程存储
    -拖拽排序，优先级别
    。。。
    帮我谐音更React 代办清单页面，支持新增、删除任务

-先规划，再编码
```
遵守胶水编程思维:优先使用成熟方案，避免凭空造逻辑。
第一个阶段：只做规划，禁止输出任何代码。
1.确认技术栈
React 19 + Tailwindcss + useState
2.梳理功能边界
-新增代办，删除代办，切换完成状态
-不做本地持久化，筛选、拖拽等功能
3.拆分模块（乐高组件）
输入框组件、待办条目组件、列表容器组件、
4.定义数据流
useState 存储 task 数组 数据结构：
{id，text，completed}
5.输出这份完整规划，等待我确认无误后，再分段实现代码
```

背后逻辑 
先划定边界;防止AI 擅自多加功能，无限膨胀成屎山。
强制模块拆分（好读好维护，AI生成代码我们都要审核）
引导AI复用独立组件，预先规定数据结构，从根源减少
AI参数、字段幻觉（title，不能是text，字段不能让AI做主）。
先生成规划、审核规划、更新规划
这份规划将伴随项目开发的完整周期。

- 第二步：‘胶水’编程思维
能抄不写（github 经典，优质，经过验证的代码），能连不造（A、B、C组件 胶水）。
指挥AI 去找已经被验证过的千万次成熟组件，拼乐高一样，把它组装起来。
胶水 比喻，可以粘合，少量(AI 生成的)，产生幻觉和屎山的可能性大大降低

胶水本身不创造零件，只负责把现成零件连在一起，你只负责写衔接、调用、流转的粘合代码，把各个模块连通

轮子别人做好，你只做胶水; 胶水不生产零件，只负责粘合零件。

## 举例
React 待办 连贯演示
我们已经完成项目规划、现在正式写代码，对比两种方式：

- 错误示范(指令)
  从零造零件，高幻觉风险
  '帮我写React 待办清单的拖拽排序功能'
  AI 很可能凭空写一套拖拽逻辑，自行实现坐标监听，排序算法
  问题：手写拖拽排序逻辑边界case 很多(规划写的很复杂)，容易出现幻觉bug，而且难以维护

遵守胶水编程原则：绝不从零自研底层逻辑，优先选择社区长期验证成熟的组件

当前需求：给待办列表增加拖拽排序
1. 先调研：React 生态成熟的拖拽库，优先选用react-beautiful-dnd(业内广泛使用)
   npm i react-beautiful-dnd
   <react-beautiful-dnd>
   ...list items
   </react-beautiful-dnd>
2. 不要自己手写拖拽底层代码，只做粘合工作
3. 输出内容顺序：
   安装依赖命令，把现有TodoList 组件和react-beautiful-dnd 进行衔接。
   只写模块之间适配、数据流转的粘合代码

- 第三步 用元方法论让AI 自我进化
  cc/codex 记忆模块、harness 架构
  可以不断帮我们优化提示词
  a (阿尔法)提示词 怎么干活，规范就会生成？欧米茄提示词
  去根据生成结果，打分，判断，AI 系统不断进化

# v005 大纲

## 标题
从 Git 到版本思维：一个 AI Native 开发者的基本功补全

## 结构

### 引言
- 回顾系列 v001-v004 的脉络：从 OPC 概念到 Prompt 设计，从 AI Agent 实战到工作流进化
- 引出新问题：过度依赖 AI 写代码，基本功越来越"薄"
- 决定回归基础，学 Git
- 这不是 Git 教程，而是为什么 AI Native 开发者需要补基本功的思考

### 一、为什么要学 Git？
- 之前版本管理全靠 AI，对 Git 理解停留在"点提交按钮"
- 具体场景：改代码后新方案没跑通，想回到之前的状态
- 核心类比：做游戏需要存档，写代码同样需要
- 基本功解决的问题不是"能不能做"，而是"安不安全、可不可持续"
- 呼应 v004 /plan 模式的"先对齐再执行"哲学

### 二、三个核心概念：仓库、状态、快照
- git init：文件夹 → 仓库，文件:文件版本 = 1:n 的思维转变
- git status：时刻确认当前状态，和 /plan 模式本质一致
- git add + git commit：两次确认一次存档，防误操作设计
- 呼应 v002 Prompt 设计——每一步都值得停下来确认

### 三、分布式与协作：一人公司的版本管理
- 分布式版本控制 vs "最终版_v3" 的文件夹
- 本地仓库 + 远程仓库 + push
- OPC 场景下的远程仓库：备份、多设备同步、发布
- 一人公司不等于单机开发

### 四、Git 与 AI Agent：两种"版本管理"
- CLAUDE.md（AI 理解版本）vs Git（代码历史版本）
- 对比表格
- 版本管理的决策仍然是人的事
- 呼应 v002 "领域知识是护城河"

### 五、配置与开始：建立自己的 Git 工作流
- git config 全局身份配置
- "写代码 → review → add → commit → push" 的工作流
- 每一次提交都是有意识的决策

### 结语
- AI Native 开发者也不能跳过基本功
- 反问："一个人 + AI，能持续做多久？"——取决于基本功
- 学 Git 是补基础的第一步
- 呼应 v001 OPC 的前提：愿意去学这七个角色的基本功

# v007 大纲

## 标题
从 AI 开发到业务落地：一个 AI Native 开发者的 FDE 初探

## 结构

### 引言
- 回顾系列六篇文章的进化路径：OPC（认知）→ Prompt（沟通）→ Agent（工具）→ CLI（工作流）→ Git（版本）→ 模块化（架构）
- 引出新问题：技术能写了，项目能搭了，然后呢？AI 怎么真的产生商业价值？
- 引入 FDE（前沿部署工程师）——目前 AI 圈最火的岗位
- 核心观点：技术的终点不是代码写完了，而是业务真正用起来了

### 一、AI 工程师的四段进化
- 从笔记中的进化链展开：Software Engineer → Prompt Engineer → Agent Engineer → FDE Engineer
- 映射到博客系列：
  - v001：传统开发 + AI 辅助（人是主力，AI 辅助）
  - v002：Prompt Engineer（AI 为主，人表达意图）
  - v003-v004：Agent Engineer（AI 自主构建，可靠执行）
  - v007：FDE Engineer（AI 结合业务，落地价值）
- 每一阶段都在提升抽象层次和杠杆效应
- FDE 不取代前几个阶段，而是整合它们
- 呼应 v001 OPC 的"一人分饰七角"——FDE 是把这种多角色能力带入企业场景

### 二、从卖模型到卖结果：AI 行业的新拐点
- 过去：拼模型参数、上下文长度、跑分
- 现在：拼谁真正把 AI 落地在企业业务中
- 标志性事件：OpenAI 成立 Tomoro、Anthropic 与高盛/黑石合作
- 企业买 AI 不是买 API 或 token——企业要的是降本、提效、增长、风控
- FDE 是站在客户现场的 AI 工程负责人
- 呼应 v001 OPC：OPC 是你自己成为一人公司；FDE 是你成为 AI 能力和企业需求之间的桥梁
- 思维转变：从"AI 能做什么"到"业务需要什么"

### 三、FDE 做什么：影楼里的 AI 改造
- 具体案例：影楼的 AI 改造
  1. 自动化修图
  2. 自动生成宣传视频/文案，推送到抖音/快手/小红书
  3. 获客线索 Agent
  4. To B + To C 双重收入模式
- 从这个案例提炼 FDE 通用工作流：理解流程 → 识别 AI 适配环节 → 连接数据/系统/工具 → 搭建 Agent 工作流 → 评测 → 部署
- 核心概念：AI 工作流编排（企业流水线）
- 呼应 v003 Agent：FDE 的 Agent 不只是写代码，而是连接真实业务系统
- 呼应 v006 模块化：同样的分而治之思想，现在应用在业务流程层面

### 四、中国 AI 生态：FDE 的独特土壤
- 中国 AI 产品矩阵：豆包、Coze、Trae、剪映——完整的 AI 平台生态
- Coze 深度介绍：
  - AI 智能体
  - AI 应用（零代码/低代码）
  - AIGC 内容生成（多模态）
  - 节点式编排、流程串联
- 中国为什么适合 FDE：平台集成度高、企业接受快、SME 市场庞大
- 呼应 v001 OPC：中国的 AI 工具生态让"一人公司"更加可行
- 呼应 v003 Agent：Coze 把 Agent 构建权交到了每个人手上——零代码 FDE 成为可能

### 五、FDE 对 AI Native 开发者的意义：第四次跃迁
- 回顾系列中的抽象层次跃迁：
  - 写代码（逐行编程）
  - 写 Prompt（描述意图）
  - 做架构（设计系统）
  - 做业务（交付价值）
- FDE 需要三种能力：领域知识 + AI 工程 + 商业理解
- 领域知识是新的"护城河"
- AI Native 开发者的终极形态：连接 AI 和业务的桥梁
- 呼应 v001 的七个角色：FDE 需要从业务端理解所有七个角色，在技术端用 AI 执行它们

### 结语
- FDE 不只是岗位名称，更是一种思维转变：从"用 AI 构建"到"为业务部署 AI"
- 系列进化不是线性，而是螺旋上升——每个新概念都在重新定义前面的概念
- FDE 之后是什么？保持学习，保持好奇
- **Be AI Native.**

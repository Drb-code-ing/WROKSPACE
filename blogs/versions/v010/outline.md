# v010 大纲

## 标题
从 API 到 Agent 实战：一个 AI Native 开发者的 Hermes Agent 初体验

## 结构

### 引言
- v009 从理论层面理解了 Agent 的"发动机"——LLM API 调用
- 今天，v010，第一次真正和一个完整的 AI Agent 系统深度交互
- 不是用 Claude Code 写代码，而是**和 Agent 本身对话**——了解它、配置它、使用它
- 核心收获：从"用 Agent 做事"到"理解 Agent 是什么"的认知跃迁
- 三个主题：① Agent 的多平台架构 ② Agent 的资源管理（Token、记忆） ③ Agent 的局限性与现实

### 一、Hermes Agent：一个开源 AI Agent 的全貌
- Hermes Agent 是什么：Nous Research 出品的开源 AI Agent 框架
- 和 Claude Code / Codex 的异同
  - 相同点：工具调用、文件操作、代码执行
  - 不同点：多平台支持、持久记忆、技能系统、自我改进
- 核心特性
  - 20+ LLM 提供商支持（OpenRouter、Anthropic、小米 MiMo 等）
  - 多平台网关（微信、Telegram、Discord、Slack...）
  - 持久记忆（跨会话记住用户偏好）
  - 技能系统（从经验中学习，保存可复用流程）
- 呼应 v003：Claude Code 是"帮你干活的工具"，Hermes 是"帮你干活且能学习的伙伴"

### 二、多平台网关：Agent 的"触手"
- 一个 Agent，多个入口
  - 终端 CLI（命令行交互）
  - WebUI（浏览器图形界面）
  - 微信/Telegram/Discord（消息平台）
- 网关架构：你的电脑是"服务器"，各平台是"客户端"
  - 关机 = 网关停止 = 所有平台无法访问
  - 需要"始终在线"的设备（云服务器/树莓派）
- 服务化部署
  - `hermes gateway install` 安装为系统服务
  - 开机自启，后台运行
- 呼应 v001 OPC：一人公司的 Agent 需要 24 小时在线
- 呼应 v004 CLI：CLI 是最轻量的交互方式，但网关让它无处不在

### 三、Token 消耗：Agent 的"燃料表"
- 什么是 Token：LLM 处理文本的最小单位
- 今天的消耗数据
  - 输入 Token：55,555（系统提示 + 技能 + 对话历史）
  - 输出 Token：5,781（Agent 的回复）
  - 缓存读取：1,021,440（重复内容的缓存）
- 为什么输入比输出多得多？
  - 系统提示（System Prompt）很长——包含 Agent 人格、技能列表、环境信息
  - 每次对话都要发送完整上下文
  - 缓存机制减少了重复计算的成本
- 成本意识：AI Agent 不是免费的，每次对话都有成本
- 呼应 v005 Git：Git 管理代码版本，Token 管理"认知成本"
- 呼应 v008 编程基本功：优化代码 = 优化 Token 消耗

### 四、记忆与技能：Agent 的"长期记忆"
- 持久记忆（Memory）
  - 跨会话记住用户偏好（中文、工作环境、常用路径）
  - 存储在 ~/.hermes/memory.json
  - 每次对话自动注入
- 技能系统（Skills）
  - 从经验中学习，保存可复用的流程
  - 例如：浏览器配置、网关管理、文件操作
  - 技能可以分享、更新、版本控制
- 对比人类学习
  - 人类：经验 → 记忆 → 技能 → 习惯
  - Agent：对话 → Memory → Skills → 自动加载
- 呼应 v002 Prompt：Prompt 是短期指令，Memory 是长期知识
- 呼应 v006 模块化：技能就是 Agent 的"模块化知识"

### 五、浏览器自动化：Agent 的"眼睛"与局限
- 尝试让 Agent 打开 Edge 浏览器查看稀土掘金
- 结果：失败——Windows 环境兼容性问题
- 失败原因分析
  - Chrome/Edge 启动参数不兼容
  - 浏览器路径检测问题
  - Windows 权限限制
- Agent 的局限
  - 不是万能的——受限于操作系统、权限、工具链
  - 需要"人机协作"——Agent 做不到的，人来补充
- 成功的部分
  - 文件系统访问（E 盘 WROKSPACE）
  - 终端命令执行
  - 截图功能（PowerShell 调用）
- 呼应 v007 FDE：了解工具的边界，才能做出正确的技术选择
- 呼应 v009 Python vs JS：每个工具都有适用场景

### 六、从使用者到理解者：认知跃迁
- v003 的状态：用 Claude Code 做事，但不知道里面发生了什么
- v010 的状态：和 Agent 对话，了解它的架构、限制、成本
- 认知变化
  - "Agent 是黑箱" → "Agent 是可配置的系统"
  - "AI 是免费的" → "每次对话都有 Token 成本"
  - "AI 无所不能" → "AI 有明确的边界"
- 这种认知对 FDE 的意义
  - FDE 需要评估 Agent 的能力边界
  - FDE 需要计算 Agent 的使用成本
  - FDE 需要设计人机协作的工作流
- 呼应 v001 OPC：一人公司不是"一个人+AI"，而是"一个人+理解AI的能力"

### 结语
- 三件事：① Agent 是可配置的系统，不是黑箱 ② 多平台架构让 Agent 无处不在 ③ 了解边界才能用好工具

  - v010：Agent 实战（架构、成本、边界）

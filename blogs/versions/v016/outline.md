### 一、线性数据结构：栈和队列
- **栈（Stack）**：FILO（后进先出）
  - 生活类比：叠盘子，最后放的最先拿
- **队列（Queue）**：FIFO（先进先出）
  - 生活类比：排队，先到先服务
- 基本操作：push、pop、peek、empty

### 二、用栈模拟队列
- 核心思想：两个栈实现队列的 FIFO 特性
- 栈1 负责入队，栈2 负责出队
- 当栈2 为空时，把栈1 的元素全部倒入栈2

### 三、JavaScript 的面向对象：不走寻常路
- 不需要 class 也可以实现面向对象
- 函数是一等对象，可以有属性和方法
- 普通函数调用：this 指向全局对象（window）
- new + 构造函数调用：this 指向新创建的对象

### 四、new 运算符的执行过程
1. 创建一个空对象，this 指向新创建的对象
2. 构造函数执行，this 上添加属性
3. 构造函数有 prototype 属性，指向原型对象
4. 原型对象上的方法，实例也可以使用

### 五、原型式面向对象
- JS 没有类，只有对象
- MyQueue.prototype 是一个对象
- 实例对象有 __proto__ 属性，指向原型对象
- 沿着原型链查找属性，直到 Object 最顶层（终点是 null）
- 先在自己身上查找，没有再沿原型链查找
- 任何函数有 prototype 属性，指向原型对象
- 原型对象上有 constructor 属性，指向构造函数

### 六、JS 的执行机制：代码是怎么跑起来的
- **执行上下文对象**：变量环境（var/function）、词法环境（let/const）、执行的代码
- **调用栈（Call Stack）**：V8 引擎管理函数调用关系的数据结构
  - 编译总在执行前一刻发生
  - 全局和函数体的编译生成执行上下文对象，存入调用栈
  - 函数执行完毕后，执行上下文弹出销毁
- **编译过程**：
  - 创建执行上下文对象
  - 找形参和变量声明，值设为 undefined
  - 统一形参和实参的值
  - 找函数声明，值设为函数对象
  - 这就是变量提升（hoisting）的本质
- **let/const 与块级作用域**：
  - 词法环境支持块级作用域
  - 不能重复声明，不会变量提升
  - 暂时性死区（Dead Zone）
  - 为 var 的 bug 擦屁股
- **执行流程总结**：读取代码 → 编译 → 执行

### 七、JS 的设计哲学
- 一切皆对象，没有类
- Object 是顶层对象
- Function、Array、Date、RegExp 等都是函数对象
- 原型链是 JS 继承的核心机制
- JS 是先编译再执行的语言
- 执行上下文 + 调用栈是代码运行的基础框架

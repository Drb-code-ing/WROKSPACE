# v011 大纲

## 标题
从写代码到写 Prompt：一个 AI Native 开发者的提示词工程入门

## 结构

### 引言
- v010 学了 JS 底层（作用域 / var / let / const），今天 v011 换一个方向——从"写代码"到"写提示词"
- 学习来源：吴恩达 deeplearning.ai 的 Prompt Engineering 课程
- 核心转变：代码的主力是 LLM 不是人，人的工作变成了"用自然语言编程"
- 三个主题：① Prompt 的五个构建块 ② 四条核心规则的实战 ③ LLM 幻觉——当 AI 一本正经地胡说八道

### 一、get_completions 函数：LLM API 的"第一行代码"
- 从 v009 的 Python 基础到今天调用 DeepSeek API
- get_completions 的设计：参数默认值、工具函数的复用性
- LLM API 的两种接口
  - completions：纯文本生成（prompt → response）
  - chat.completions：对话形式（messages 数组，支持 system/user/assistant 多轮对话）
- 呼应 v009：Python 的函数 + API 调用，是 AI 工程的基础能力
- 代码示例：用 DeepSeek API 调用"什么是 vibe coding"

### 二、Prompt 的五个构建块：Goal + Input + Output + Layout + Features
- 回顾 v001 的生日卡片案例：prompt 不够清晰时，AI 靠猜，结果不好用
- 五个构建块
  - Goal（目标）：你想要什么
  - Input（输入）：给 AI 什么素材
  - Output（输出）：期望什么格式
  - Layout（布局）：结果怎么排版
  - Features（特性）：额外的功能需求
- Prompt 不是"随便说句话"，而是有结构的"需求规格书"
- 呼应 v003 落地页项目：prompt 就是 AI 时代的 PRD（产品需求文档）

### 三、规则一：清晰且具体的表达
- 清晰：让大模型理解目的，不偏离主题
- 具体：提供上下文，用分隔符标记输入文本
- 实战案例：用 ``` 反引号标记待处理文本，让 LLM 总结
- 关键洞察："清晰的指令"不等于"简短的指令"——更长的 prompt 能提供更完整的背景信息
- Python f-string 作为 prompt 模板：{text} 是字符串模板的占位符
- 呼应 v010：JS 的模板字符串 `${text}` 和 Python 的 f-string `{text}` 异曲同工

### 四、规则二：约束输出格式——JSON 的力量
- 为什么要约束格式？LLM 默认返回散文体，程序难以解析
- 实战案例：四大名著 → JSON 格式，指定 book_id / title / author / genres 字段
- 进阶技巧：在 JSON key 中加注释（自然语义的加持），让输出更丰富
- 核心认知：Prompt 不只是"对话"，更是"编程"——你在用自然语言写接口规范
- 呼应 v006 模块化：JSON 约定就是模块之间的"接口协议"

### 五、规则三：分布式提示——让 AI 一步一步来
- 什么是分布式提示？把复杂任务拆成多个步骤
- 实战案例：泡茶指令的分步整理
  - 输入：一段描述泡茶的文字
  - Prompt 要求：如果文本包含操作指令，按"步骤一、步骤二..."重新整理
  - 输出：清晰的分步指令
- 进阶案例：多步骤 NLP 任务链
  - 概括 → 翻译成法语 → 提取人名 → 输出 JSON
  - 一个 prompt 完成四步操作
- 关键洞察：复杂任务不要一次性交给 LLM，拆成步骤效果更好
- 呼应 v008 数组去重的多种思路：分步思考是编程思维的核心

### 六、规则四：Few-shot 提示——用示例教 AI
- 什么是 Few-shot？在 prompt 中提供 2-5 个示例，引导模型理解任务格式
- 实战案例：诗歌风格匹配
  - 给出"耐心"的诗体回答作为示例
  - 让 LLM 用同样的风格回答"韧性"
  - 输出：能折不断青竹的暴雪...（完美匹配风格）
- 核心认知：Few-shot 不需要微调模型，只需要"教"它几次
- 呼应 v007 FDE：Few-shot 的本质是"用最少的样本做最大的事"——和 FDE 的快速交付理念一致

### 七、LLM 幻觉：当 AI 一本正经地胡说八道
- 什么是幻觉？LLM 生成看似合理但完全虚构的内容
- 实战案例一：博伊品牌 AeroGlide 超薄智能电动牙刷
  - 这个产品根本不存在
  - 但 LLM 编造了完整的产品介绍：40000次/分钟震动、IPX7防水、30天续航...
  - 甚至连品牌名都不确定（"博伊"还是"博皓"），但依然自信满满
- 实战案例二：蜜雪冰城的滑雪装备
  - 蜜雪冰城从未推出过滑雪装备
  - LLM 编造了"雪王IP衍生周边"、"网友二创设计"等内容
  - 虽然最后承认"不是真实商品"，但中间的大段描述极具迷惑性
- 为什么会有幻觉？LLM 本质是"概率预测下一个 token"，不是"检索事实"
- 如何应对幻觉？
  - 不要盲信 LLM 的输出，尤其是涉及具体品牌、产品、数据时
  - 用"请基于以下事实回答" + 提供参考文本来约束
  - 关键信息一定要人工验证
- 呼应 v001：vibe coding 的最大风险就是幻觉——AI 生成的代码可能有隐蔽 bug

### 结语
- 三件事：① Prompt 是有结构的"需求规格书" ② 四条规则减少 LLM 的随机性 ③ 幻觉是 LLM 的本质缺陷

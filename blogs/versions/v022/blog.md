# JS 的八种数据类型与内存分配：一个 AI Native 开发者的语言底层理解

## 引言

v020 学了 JS 的执行机制——单线程、Event Loop、Promise。那是"运行时"层面的理解。

v021 学了线性数据结构——栈、队列、链表。那是"数据怎么存"层面的理解。

今天回到 JS 语言本身，把**数据类型**搞清楚。

写 JS 每天都在用 `let`、`const`、`typeof`，但你真的知道 JS 有多少种类型吗？`null` 和 `undefined` 到底有什么区别？为什么 `0.1 + 0.2 !== 0.3`？原始类型和引用类型在内存里怎么存的？这些看似基础的问题，背后是 JS 语言设计的核心逻辑。

**类型系统是 JS 的第一层地基。** 今天把它打牢。

## 一、ECMA262 规范：八种数据类型全景

JS 的数据类型不是"差不多有几种"，而是由 ECMA262 规范精确定义的：

```
JS 数据类型（8种）
├── 原始类型（Primitive Types）—— 7种
│   ├── Number      —— 数值
│   ├── String      —— 字符串
│   ├── Boolean     —— 布尔值
│   ├── null        —— 空引用
│   ├── undefined   —— 未定义
│   ├── Symbol      —— 唯一标识符（ES6 新增）
│   └── BigInt      —— 大整数（ES6 新增）
└── 引用类型（Reference Type）—— 1种
    └── Object      —— 对象（包含 Array、Function、Date 等）
```

**核心区分：原始类型 vs 引用类型。**

| | 原始类型（Primitive） | 引用类型（Reference） |
|---|---|---|
| **存储位置** | 栈内存（Stack） | 堆内存（Heap） |
| **赋值方式** | 拷贝值 | 拷贝引用（地址） |
| **可变性** | 不可变 | 可变 |
| **typeof 结果** | 对应类型名 | `"object"`（函数返回 `"function"`） |

> ES6 以前 JS 只有 6 种类型（Number、String、Boolean、null、undefined、Object）。ES6 新增了 Symbol 和 BigInt，扩展到现在的 8 种。

## 二、原始数据类型详解

### Number —— JS 唯一的数值类型

JS 没有 int / float / double 的区分——**所有数字都是 Number**（64 位双精度浮点数）。

```javascript
let a = 42        // 整数
let b = 3.14      // 小数
let c = Infinity  // 无穷大
let d = NaN       // Not a Number（但它 typeof 是 number）
```

这和 C++/Java 完全不同——它们有 byte、short、int、long、float、double 一堆数值类型。JS 选择简单，用一个 Number 搞定一切，代价是精度有限。

### String —— 不可变的字符序列

```javascript
let s = "hello"
s[0] = "H"        // ❌ 不会报错但无效——字符串不可变
console.log(s)     // "hello"
```

字符串是原始类型，不可变。任何"修改"操作（如 `toUpperCase()`）都返回新字符串。

### Boolean —— 只有两个值

```javascript
let t = true
let f = false
```

简单直接，没有歧义。

### null —— 一个有意为空的引用

```javascript
let obj = null    // 明确表示：这里应该有一个对象，但现在是空的
```

**null 的类型用 typeof 检测会返回 `"object"`**——这是 JS 的一个历史 Bug（typeof null === "object"），但已经无法修复，因为大量代码依赖这个行为。

### undefined —— 未定义，系统默认的空值

**五种场景下会出现 undefined：**

```javascript
// 1. 变量声明但未赋值
let a
console.log(a)  // undefined

// 2. 访问对象不存在的属性
let obj = {}
console.log(obj.name)  // undefined

// 3. 函数没有返回值
function noReturn() {}
console.log(noReturn())  // undefined

// 4. 访问不存在的数组索引
let arr = [1, 2, 3]
console.log(arr[10])  // undefined

// 5. 函数参数未传值
function fn(x) { console.log(x) }
fn()  // undefined
```

**关键认知：undefined 是 JS 引擎自动赋予的"空"，是系统级的；null 是开发者主动赋予的"空"，是用户级的。**

## 三、null vs undefined —— 空的不同面孔

这个问题面试必考。两者的核心区别：

| | null | undefined |
|---|---|---|
| **语义** | 有意设置为空的对象引用 | 变量未被初始化或不存在 |
| **含义** | 某处应该有个值，但目前没有 | 某处从未有过值 |
| **赋值者** | 开发者主动设置 | JS 引擎自动赋予 |
| **typeof** | `"object"`（历史 Bug） | `"undefined"` |
| **用途** | 清空变量释放内存、表示空对象 | 系统默认的"没有" |

```javascript
// null —— 主动清空，触发垃圾回收
let largeObject = { data: new Array(10000000).fill("x") }
largeObject = null  // 原来的大对象失去引用，GC 可以回收

// undefined —— 系统默认
let x              // 没赋值，默认 undefined
```

**记住一句话：null 是"我知道这里应该有值，我先设为空"；undefined 是"这里从来就没有过值"。**

## 四、拷贝式赋值 vs 引用式赋值 —— 内存视角

这是类型系统最底层的区别。

### 原始类型：拷贝式赋值

```
栈内存：
┌───────┐
│ a: 1  │  ← 创建 a，存值 1
│ b: 1  │  ← 创建 b，拷贝 a 的值 1（独立副本）
└───────┘

b = 2 之后：
│ a: 1  │  ← a 不受影响
│ b: 2  │  ← b 是独立副本，修改不影响 a
```

```javascript
let a = null
let b = a      // 拷贝：b 拿到 a 的值（null）
b = 2          // 修改 b，a 不受影响
console.log(a) // null（不变）
```

原始类型的值是直接存在栈内存里的，赋值就是**复印机**——复制一份给你，各过各的。

### 引用类型：拷贝地址（共享同一份数据）

```
栈内存                堆内存
┌────────────────┐   ┌──────────────────┐
│ obj:  0xA01 ───┼──→│ { name: "Alice" } │
│ obj2: 0xA01 ───┼──→│                  │
└────────────────┘   └──────────────────┘
两个变量指向同一块堆内存！
```

```javascript
let obj = { name: "Alice" }
let obj2 = obj         // obj2 拷贝的是 obj 的地址（引用），不是对象本身
obj2.company = "快手"  // 改的是堆里那块数据

console.log(obj)       // { name: "Alice", company: "快手" } ← obj 也变了！
```

**obj 和 obj2 指向的是堆里同一个对象。** 通过 obj2 修改属性，obj 也能看到变化。这和原始类型的"复印机"完全不同。

### 为什么这样设计？

- **原始类型** 大小固定（Number 8 字节、Boolean 4 字节...），编译阶段就能算出来，直接存栈里——快。
- **对象** 大小不固定，一个对象里可以嵌套无数属性和嵌套对象——编译器算不出需要多少空间，只能动态分配在堆里。栈里存一个"地址"（64 位指针）指向堆里的实际数据。

## 五、Symbol：唯一的标识符

```javascript
console.log(Symbol('张志') === Symbol('张志'))  // false！
console.log(typeof Symbol('张志'))              // "symbol"
```

**每次调用 `Symbol()` 都返回一个全世界独一无二的值**——即使传入相同的标签（label）字符串。标签只是给人看的调试信息，不影响唯一性。

主要用途：**作为对象属性的 key，防止命名冲突。**

```javascript
let obj = {
  [Symbol()]: 'value',   // 这个属性用 Symbol 做 key
  prop: "2"              // 这个属性用字符串做 key
}
```

用 Symbol 做 key 的属性：
- 不会被 `for...in` 遍历到
- 不会被 `Object.keys()` 返回
- 实现了"私有属性"的效果（但不是真正的 private）

**Symbol 的出现解决了什么问题？** 大型项目里，大家都在往同一个对象上加属性，用字符串做 key 很容易重名覆盖。Symbol 保证了你加的属性绝对不与别人的冲突。

## 六、BigInt 与 Number 精度问题

### Number 的精度陷阱

```javascript
console.log(0.1 + 0.2)  // 0.30000000000000004 ≠ 0.3！
```

**为什么？** JS 的 Number 用 IEEE 754 双精度浮点数（64 位二进制）来表示所有数字。很多十进制小数（比如 0.1、0.2）在二进制中是**无限循环**的，就像十进制的 1/3 = 0.3333... 一样。存入 64 位空间时被截断，产生了舍入误差。

这不是 JS 的 bug——所有用 IEEE 754 的语言（C++、Java、Python）都有这个问题。

**应对方案：**
- 涉及金额计算，转成整数（分）再算，最后除以 100
- 用 `Number.EPSILON` 判断两个浮点数是否"足够接近"

### BigInt：ES6 的大数解决方案

JS 的 Number 安全范围是 `-2^53 ~ 2^53`（约 ±9 千万亿）。超出这个范围，精度完全丢失。

```javascript
let num1 = 999999999999999999999999999999999999999999999999999999999999999n
let num2 = 123456789098765433467324577654789008733233456899003466788924243n
console.log(num1 + num2)  // 精确相加！
console.log(typeof num1)  // "bigint"

// 注意：BigInt 只能和 BigInt 运算
console.log(num1 + 1n)    // ✅
// console.log(num1 + 1)  // ❌ TypeError: Cannot mix BigInt and other types
```

BigInt 用 `n` 后缀标记。它没有精度上限——可以表示任意大的整数。适合密码学、高精度计算等场景。

> **JS 不擅长精密计算。** 这也是为什么 JS 更多用于 Web 交互（I/O 密集），而不是科学计算（计算密集）。每种语言有它的主战场。

## 七、内存分配：栈与堆

回到计算机体系结构——冯·诺依曼架构：运算器、控制器、存储器、输入设备、输出设备。

我们写的代码存在硬盘（外存），编译后调入内存（RAM）。**执行时，函数调用被推入调用栈（Call Stack），在栈内存中分配空间。**

```
┌──────────────────────────────────┐
│          栈内存（Stack）          │
│  ┌────────────────────────────┐  │
│  │ 全局执行上下文               │  │ ← 栈底
│  │  ├ 变量环境（var/function）  │  │
│  │  └ 词法环境（let/const）     │  │
│  ├────────────────────────────┤  │
│  │ 函数 A 执行上下文            │  │
│  │  ├ 变量环境                 │  │
│  │  └ 词法环境                 │  │
│  ├────────────────────────────┤  │
│  │ 函数 B 执行上下文            │  │ ← 栈顶（当前执行）
│  │  ├ 变量环境                 │  │
│  │  └ 词法环境                 │  │
│  └────────────────────────────┘  │
│      快、空间小、自动管理         │
└──────────────────────────────────┘

┌──────────────────────────────────┐
│          堆内存（Heap）           │
│  ┌────────────────────────────┐  │
│  │ { name: "Alice", ... }      │  │
│  │ [1, 2, 3, 4, 5, ...]       │  │
│  │ function() { ... }          │  │
│  │ ...各种对象和数据...          │  │
│  └────────────────────────────┘  │
│      慢、空间大、GC 管理          │
└──────────────────────────────────┘
```

### 栈内存的特点

- **快** —— 连续空间，指针偏移就能切换上下文
- **空间小** —— 编译阶段就能算出每个函数执行上下文需要多少空间
- **自动管理** —— 函数执行完就出栈，内存自动回收
- **存原始值** —— 原始类型直接写入值

### 堆内存的特点

- **大** —— 动态分配，存不固定大小的对象
- **慢** —— 通过指针（地址/引用）访问
- **GC 管理** —— 垃圾回收器定期清扫不再被引用的对象

**当一个函数执行完毕，执行上下文出栈销毁，但堆里分配的对象不一定会立刻销毁——** 只要还有别的变量引用着它，GC 就会保留。这就是"闭包"能工作的底层原理。

## 八、内存手动释放

JS 有垃圾回收（GC），大多数时候不用手动管内存。但有一种情况需要主动释放：

```javascript
let largeObject = {
  data: new Array(10000000).fill("hgh")  // 占用大量内存
}

// 不再需要这个大对象时，主动断掉引用
largeObject = null  // GC 会在下次运行时回收这块内存
```

**把变量设为 `null`，等于告诉 GC："我不再需要这块数据了，你可以回收它。"** 这对于处理大数组、大对象、缓存数据来说是一个好习惯。

## 结语

今天从 ECMA262 规范出发，把 JS 的类型系统从底层搞明白了：

1. **八种类型全景** —— 7 种原始类型（Number、String、Boolean、null、undefined、Symbol、BigInt）+ 1 种引用类型（Object）
2. **原始类型详解** —— Number 一统数值、String 不可变、Boolean 简单直接
3. **null vs undefined** —— null 是开发者主动设的空（释放内存），undefined 是 JS 引擎默认的空（从未有过值）。五个场景出现 undefined
4. **拷贝 vs 引用** —— 原始类型拷贝值（复印机，各过各的），引用类型拷贝地址（共享堆里的同一份数据）。这是面试必考点
5. **Symbol** —— ES6 新增，每次调用返回唯一值，防止对象属性命名冲突
6. **BigInt 与精度** —— `0.1 + 0.2 !== 0.3` 是 IEEE 754 浮点数的通用问题，BigInt 用 `n` 后缀表示任意大整数
7. **栈与堆** —— 栈快但小（存原始值 + 执行上下文），堆大但慢（存对象，GC 回收）
8. **内存释放** —— `= null` 主动断引用，触发 GC

v020 搞懂了"JS 怎么运行"（Event Loop），v021 搞懂了"数据怎么存"（数据结构），今天搞懂了"数据是什么类型"（类型系统）。**三篇文章加起来，JS 的"运行时 + 数据结构 + 类型系统"三根柱子全部立起来了。**

**类型是 JS 一切语法和 API 的起点。** 搞懂了类型，才能理解为什么 `===` 和 `==` 有区别、为什么 `typeof null === "object"`、为什么函数参数有时候"莫名其妙"地被改变。

地基打好了，下一步该上脚手架了——原型链与面向对象。
